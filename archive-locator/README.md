# 广播档案馆节目定位服务（本地模拟）

用 **TypeScript + Node.js + SQLite** 实现的节目定位服务，**零外部依赖**
（TypeScript 由 Node ≥ 22.18 原生类型擦除直接运行，SQLite 用内置 `node:sqlite`，
`npm install` 无包可装、瞬间完成）。

三个可启动组件 + 一条验证命令：

| 组件 | 启动 | 说明 |
|---|---|---|
| 模拟站点 | `npm run site` | 本地模拟清单站点（不依赖真实外站），端口 4181 |
| 同步入口 | `npm run sync` | 采集器守护进程，断点续采、暂停避让、令牌恢复、更正续采 |
| 查询接口 | `npm run api` | 只读查询服务，端口 4182，独立于采集器进程 |
| 一键验证 | `npm run verify` | 自动起停全部组件，约 11 秒（远低于 80 秒）跑完 8 阶段 42 项检查 |

## 快速开始

```bash
npm install        # 无依赖，瞬间完成（安装时间单算）
npm run verify     # 一条命令验证：采集恢复、修订切换、节目定位
```

手动分步启动（三个终端）：

```bash
npm run site                              # 模拟站点 http://127.0.0.1:4181
SITE_URL=http://127.0.0.1:4181 \
DB_PATH=./data/archive.db POLL_MS=500 \
  npm run sync                            # 采集器
DB_PATH=./data/archive.db PORT=4182 \
  npm run api                             # 查询接口 http://127.0.0.1:4182
```

环境变量：`PORT`（site/api 端口）、`SITE_URL`、`DB_PATH`、`POLL_MS`（采集轮询间隔）。

## 领域模型

- **母带 / 时间轴版次**：每盘母带有若干时间轴版次（各有时长；同一版次的时长也可能被站点调整）。两类清单的每次修订都标明所用版次。
- **修订号与版次号（edition）**：站点会以**同一修订号**发布更正稿或原样重发，每次重发都分配递增的 `edition`。
  每个 edition 在本地各占一行不可变修订，改稿前后的页物理隔离，**绝不会拼成一份**；旧 edition 立即从索引下架，
  针对它的翻页令牌申请返回 `409 EDITION_SUPERSEDED` 引导重新对账。
- **页哈希与未改页复用**：索引和每页响应都带 `pageHash`。新 edition 登记时，哈希与本地历史 edition（含未采齐被放弃的行）
  相同的页直接整页拷贝复用、不发任何网络请求，只抓取真正变化的页；采集器重启后同样先复用再续采。
  续采始终从「第一个缺页」开始，不依赖连续进度计数。
- **节目单**：节目在母带时间轴上的时间段；每次修订给出整盘母带的完整节目单。
- **修复清单**：母带区段在各数字副本中的位置；修复时剪掉损坏录音（损坏记录），
  并支持分段变速（`rate` 段内恒定，副本时长 = 母带时长 / rate）。
- **生效规则**：每盘母带查询采用「两类清单均已采齐」的**最新共同时间轴版次**；同版次下节目单与修复清单必须选择
  **发布时长一致的一对**完整修订——同版次改时长时站点同时重发两类清单，只有一类采齐则找不到匹配对子，
  既有生效指针保持不动（继续提供原有定位），两类都采齐后才在单个 SQLite 事务内一起切换
  **时长、播放位置与缺失区段**；同对子内同侧取最新 (revision, edition)。被新版清单移除的记录随该修订一并撤下。
- **可用性**：查询接口只读 SQLite（WAL），与采集器进程隔离——同步中、来源暂停、
  采集器重启期间，查询持续提供此前可用结果；已采齐的修订即使被站点撤下也继续可用。

## 查询接口（4182）

| 路由 | 说明 |
|---|---|
| `GET /tapes` | 母带列表及当前生效版次 |
| `GET /tapes/:tape` | 母带视图：节目单 + 各副本可播放时间段 + 该副本缺失的母带区段 |
| `GET /tapes/:tape/programs` | 当前生效节目单 |
| `GET /tapes/:tape/programs/:pid` | 节目视图：母带范围 + 各副本可播放时间段 + 缺失区段 |
| `GET /programs/:pid` | 按节目跨母带查询 |
| `GET /sync/status` | 同步进度：各来源会话/暂停状态、每修订进度（已采/总页数）、待补齐清单已采到的损坏记录位置 |
| `GET /health` | 存活检查 |

响应示例（`GET /tapes/T1/programs/P2`，时间为毫秒）：

```json
{
  "tapeId": "T1", "timelineVersion": 1, "durationMs": 3600000,
  "programRevision": 1, "programEdition": 2,
  "restorationRevision": 1, "restorationEdition": 1,
  "program": { "id": "P2", "title": "戏曲选段·修订版", "masterRange": [900000, 2400000] },
  "copies": [
    { "copyId": "C1",
      "playable": [ { "master": [900000, 1200000], "copy": [900000, 1200000] } ],
      "missing":  [ { "master": [1200000, 1500000], "note": "磁带霉变，信号丢失" } ] }
  ]
}
```

无共同版次（或无时长匹配对子）时返回 `404 NO_ACTIVE_VERSION`；节目不在当前生效修订中时返回 `404 PROGRAM_NOT_FOUND`。

## 模拟站点协议（4181）

- `GET /api/sources` — 来源（母带）列表
- `POST /api/sources/:tape/session` — 建立会话；**站点同时轮换签名令牌**；暂停中返回 `423 {pausedUntil}`
- `GET /api/sources/:tape/index?sessionId=` — 时间轴版次（含当前时长）+ 在架修订索引
  （每条附 `edition`、`durationMs` 与每页 `pageHashes`，以及当前签名令牌）
- `POST /api/sources/:tape/page-tokens` — 申请**一次性翻页令牌**（请求带 `edition`）；
  修订已撤下返回 `410`，edition 已被更正取代返回 `409 EDITION_SUPERSEDED`
- `GET /api/sources/:tape/page?sessionId=&pageToken=&sig=` — 取页。
  `sig = sha256(签名令牌|会话|翻页令牌)`，随站点刚发出的令牌和当前会话变化；
  签名过期返回 `409 STALE_SIGN_TOKEN`（附新令牌，翻页令牌不消耗）；
  令牌已消费返回 `409 PAGE_TOKEN_CONSUMED`；**响应可能丢失而令牌已消费**（站点直接断开连接），
  需重新申请令牌续采。页面有 `table` / `cards` 两种排版，按页交替，并随响应携带 `edition` 与 `pageHash`。

演示控制接口：`POST /control/publish`（发布修订；同修订号再次发布即更正/原样重发，自动分配新 edition）、
`/control/pause`（暂停来源，恢复后旧会话作废、发放新会话）、
`/control/withdraw`、`/control/withdraw-after`、`/control/lose-response`、`/control/rotate-token`、`GET /control/state`。

## 同步与恢复语义

- **更正隔离**：同一修订号的每次重发各占一个不可变 edition 行，改稿前后的页物理隔离；
  采集器收到与本地行 edition 不符的页响应一律丢弃，绝不拼接。
- **未改页复用**：新 edition 按索引 `pageHashes` 从历史 edition 行（含 abandoned 行）拷贝哈希匹配的页，
  原样重发时全部页命中、零网络抓取即采齐；只改一页时只有该页产生取页请求。
- **更正期间的定位连续性**：更正稿采齐前不是 `complete`、不参与生效选择，原有完整修订继续提供定位；
  采齐的同一事务内替换更正侧。同版次改时长时，必须两类清单的新 edition 都采齐且发布时长互相匹配，
  时长、播放位置、缺口才在一个事务内一起切换，任一侧未齐期间整体保持旧档。
- **断点续采**：页级进度落库（`pages` 检查点 + `revisions.pages_done`），页入库幂等；
  采集器重启后已采齐修订直接复用不重采，未采齐的从第一个缺页继续（含跨重启的未改页复用）。
- **撤下对账**：重启/轮询时与站点索引对账——未采齐且已撤下的修订标记 `abandoned`（进度与损坏记录仍可查，
  其页仍可被后续 edition 复用），已采齐的保留可用。
- **暂停避让**：`423` 后登记 `paused_until` 并落库，期间不向该来源发任何请求；
  恢复后以新会话继续（旧会话已被站点作废）。某来源暂停或某盘采不齐时，其他来源照常同步。

## 一键验证的场景（`npm run verify`，8 阶段 42 项）

1. **首次采集**：注入「第 2 页响应丢失、令牌已消费」，采集器凭新令牌续采完成；两种排版均解析；
   T3 修复清单被中途撤下（采不齐），T1/T2 不受影响；待补齐清单可查进度与损坏记录位置。
2. **来源暂停**：T1 暂停 4 秒，期间采集器对 T1 零请求，T2 新修订照常同步生效。
3. **恢复与原子切换**：恢复后站点发放新会话；同版次节目单 rev2 生效，
   轮询验证任何一次查询结果要么全旧要么全新（无混合态）。
4. **同修订号更正与重启续采（T4）**：取页途中发布只改一页的更正 edition，采集器登记新版并按页哈希复用
   3/4 个未改页；在变化页持续丢响应、更正稿未采齐时 SIGKILL 重启——重启窗口内查询仍是旧定位，
   重启后复用不重抓、仅补采变化页，采齐后原子替换更正侧；随后原样重发全部页哈希命中、零抓取采齐。
5. **同版次改时长门控（T4）**：站点声明新时长并重发两类清单，只让节目单侧先采齐——
   门控期间时长/播放位置/缺口整体保持旧档；修复侧也采齐后，三者在同一事务一起切换到新时长。
6. **新版次生效**：T1 时间轴 v2 两侧清单采齐后切换；被移除的 P3 随修订撤下（404）。
7. **采集器重启**：SIGKILL 后站点已撤下 T1 全部 v1 修订；重启对账后已采齐修订保留复用、
   不重复抓取，T3 补齐后生效；重启窗口内查询结果不变。
8. **节目定位展示**：按母带/按节目输出可播放时间段（含 1.5x 变速段换算）与缺失母带区段。

数据文件：`data/archive.db`（手动运行）、`.verify/`（验证用，每次运行前清空）。
