# 广播档案馆节目定位服务（本地模拟）

用 **TypeScript + Node.js + SQLite** 实现的节目定位服务，**零外部依赖**
（TypeScript 由 Node ≥ 22.18 原生类型擦除直接运行，SQLite 用内置 `node:sqlite`，
`npm install` 无包可装、瞬间完成）。

三个可启动组件 + 一条验证命令：

| 组件 | 启动 | 说明 |
|---|---|---|
| 模拟站点 | `npm run site` | 本地模拟清单站点（不依赖真实外站），端口 4181 |
| 同步入口 | `npm run sync` | 采集器守护进程，断点续采、暂停避让、令牌恢复 |
| 查询接口 | `npm run api` | 只读查询服务，端口 4182，独立于采集器进程 |
| 一键验证 | `npm run verify` | 自动起停全部组件，约 12 秒（远低于 80 秒）跑完 8 阶段 46 项检查 |

## 快速开始

```bash
npm install        # 无依赖，瞬间完成（安装时间单算）
npm run verify     # 一条命令验证：采集恢复、修订切换、节目定位
```

手动分步启动（三个终端）：

```bash
npm run site                              # 模拟站点 http://127.0.0.1:4181
SITE_URL=http://127.0.0.1:4181 \
DB_PATH=./data/archive.db POLL_MS=500 \
  npm run sync                            # 采集器
DB_PATH=./data/archive.db PORT=4182 \
  npm run api                             # 查询接口 http://127.0.0.1:4182
```

环境变量：`PORT`（site/api 端口）、`SITE_URL`、`DB_PATH`、`POLL_MS`（采集轮询间隔）。

## 领域模型

- **母带 / 时间轴版次与定义版次（edition）**：每盘母带有若干时间轴版次（各有时长）。
  同一版次号的时长被修订时产生新的 **定义版次 edition**（时长不变则 edition 不变），
  旧定义在库中留痕，旧清单始终能对应到它发布时的定义。两类清单的每次修订都标明所用版次与 edition。
- **节目单**：节目在母带时间轴上的时间段；每次修订给出整盘母带的完整节目单。
- **修复清单**：母带区段在各数字副本中的位置；修复时剪掉损坏录音（损坏记录），
  并支持分段变速（`rate` 段内恒定，副本时长 = 母带时长 / rate）。
- **同号更正与内容指纹**：每份清单带 `contentHash = sha256(pageSize|全部记录)`，
  即使总页数未变，内容一改指纹就变；原样重发指纹不变。同号更正以新指纹登记为独立修订行，
  旧行保留至索引确认撤下。翻页令牌与取页均绑定指纹——翻页途中收到更正时，
  旧令牌取页返回 `410 SUPERSEDED`，新清单的页绝不会混入旧修订。
- **生效规则**：每盘母带查询采用「两类清单均已采齐、且所依据时间轴定义相同」的
  最新共同 (版次, edition) 组，同组内两侧各取最新完整修订。任一完整修订采齐时，
  生效指针在单个 SQLite 事务内切换，因此同一次查询中的时长、播放位置和缺失区段必然一起更新；
  被新版清单移除的记录随该修订一并撤下。
- **时长变更的等待语义**：时长变更（新 edition）后，只有一类清单按新定义采齐时不切换，
  旧定义的完整结果继续可查；须两侧都按新定义采齐，才在同一事务内整体切换。
  时间轴定义未变（edition 相同）时，一侧采齐可直接复用另一侧已采齐的结果。
- **可用性**：查询接口只读 SQLite（WAL），与采集器进程隔离——同步中、来源暂停、
  采集器停机/重启期间，查询持续提供此前可用结果；已采齐的修订即使被站点撤下也继续可用。

## 查询接口（4182）

| 路由 | 说明 |
|---|---|
| `GET /tapes` | 母带列表及当前生效版次 |
| `GET /tapes/:tape` | 母带视图：节目单 + 各副本可播放时间段 + 该副本缺失的母带区段 |
| `GET /tapes/:tape/programs` | 当前生效节目单 |
| `GET /tapes/:tape/programs/:pid` | 节目视图：母带范围 + 各副本可播放时间段 + 缺失区段 |
| `GET /programs/:pid` | 按节目跨母带查询 |
| `GET /sync/status` | 同步进度：各来源会话/暂停状态、每修订进度（已采/总页数、内容指纹、edition）、待补齐清单已采到的损坏记录位置 |
| `GET /health` | 存活检查 |

响应示例（`GET /tapes/T1/programs/P2`，时间为毫秒）：

```json
{
  "tapeId": "T1", "timelineVersion": 1, "timelineEdition": 1, "programRevision": 1, "restorationRevision": 1,
  "program": { "id": "P2", "title": "戏曲选段", "masterRange": [900000, 2700000] },
  "copies": [
    { "copyId": "C1",
      "playable": [ { "master": [900000, 1200000], "copy": [900000, 1200000] } ],
      "missing":  [ { "master": [1200000, 1500000], "note": "磁带霉变，信号丢失" } ] }
  ]
}
```

无共同版次时返回 `404 NO_ACTIVE_VERSION`；节目不在当前生效修订中时返回 `404 PROGRAM_NOT_FOUND`。

## 模拟站点协议（4181）

- `GET /api/sources` — 来源（母带）列表
- `POST /api/sources/:tape/session` — 建立会话；**站点同时轮换签名令牌**；暂停中返回 `423 {pausedUntil}`
- `GET /api/sources/:tape/index?sessionId=` — 时间轴版次/定义版次（edition）+ 在架修订索引
  （附当前签名令牌与每份清单的 `contentHash`、`timelineEdition`、页数）
- `POST /api/sources/:tape/page-tokens` — 申请**一次性翻页令牌**，请求须带 `contentHash`；
  修订已撤下返回 `410 WITHDRAWN`；清单已被同号更正（指纹不符）返回 `410 SUPERSEDED`（附新指纹）
- `GET /api/sources/:tape/page?sessionId=&pageToken=&sig=` — 取页。
  `sig = sha256(签名令牌|会话|翻页令牌)`，随站点刚发出的令牌和当前会话变化；
  签名过期返回 `409 STALE_SIGN_TOKEN`（附新令牌，翻页令牌不消耗）；
  令牌已消费返回 `409 PAGE_TOKEN_CONSUMED`；**响应可能丢失而令牌已消费**（站点直接断开连接），
  需重新申请令牌续采；翻页途中清单被同号更正时旧令牌返回 `410 SUPERSEDED`。
  页面有 `table` / `cards` 两种排版，按页交替；页体回带 `contentHash` 与 `timelineEdition`。

演示控制接口：`POST /control/publish`（发布修订或同号更正；`timeline` 给定时长变化自动产生新 edition，
响应回带 `contentHash`/`pageCount`）、`/control/correct-after`（指定页发出后自动以同号清单替换，复现翻页中更正）、
`/control/pause`（暂停来源，恢复后旧会话作废、发放新会话）、
`/control/withdraw`、`/control/withdraw-after`、`/control/lose-response`、`/control/rotate-token`、`GET /control/state`。

## 同步与恢复语义

- **断点续采**：页级进度落库（`pages` 检查点 + `revisions.pages_done`），页入库幂等；
  采集器重启后已采齐修订直接复用不重采，未采齐的从下一页继续。
- **同号更正**：索引按内容指纹对账。指纹变化（含总页数未变的更正）登记为新修订行从头采；
  翻页途中被更正则旧行在 `410 SUPERSEDED` 后立即 `abandoned`（已采页保留可查，新页绝不混入）。
  指纹不变的原样重发只把状态拨回，**复用全部已采页、仅从缺页续采**。
- **时长变更**：新时长产生新 edition；单侧清单按新定义采齐不生效，等两侧都采齐后
  在单事务内同时切换时长、播放位置与缺失区段，切换前旧结果完整可查。
- **撤下对账**：重启/轮询时与站点索引对账——未采齐且已撤下的修订标记 `abandoned`（进度与损坏记录仍可查），
  已采齐的保留可用。
- **暂停避让**：`423` 后登记 `paused_until` 并落库，期间不向该来源发任何请求；
  恢复后以新会话继续（旧会话已被站点作废）。某来源暂停或某盘采不齐时，其他来源照常同步。

## 一键验证的场景（`npm run verify`，约 12 秒 < 80 秒）

1. **首次采集**：注入「第 2 页响应丢失、令牌已消费」，采集器凭新令牌续采完成；两种排版均解析；
   T3 修复清单被中途撤下（采不齐），T1/T2 不受影响；待补齐清单可查进度与损坏记录位置。
2. **来源暂停**：T1 暂停 4 秒，期间采集器对 T1 零请求，T2 新修订照常同步生效。
3. **恢复与原子切换**：恢复后站点发放新会话；同版次节目单 rev2 生效，
   轮询验证任何一次查询结果要么全旧要么全新（无混合态）。
4. **新版次生效**：T1 时间轴 v2 两侧清单采齐后切换；被移除的 P3 随修订撤下（404）。
5. **采集器重启**：SIGKILL 后站点已撤下 T1 全部 v1 修订；重启对账后已采齐修订保留复用、
   不重复抓取，T3 补齐后生效；重启窗口内查询结果不变。
6. **同号更正与时长变更**：
   - A1 总页数未变的同号更正：新指纹独立成行采齐、旧行保留，时间轴定义未变时另一侧已采齐结果直接复用；
   - B 翻页中收到更正：旧指纹修订收 `SUPERSEDED` 后停在 2/3 页放弃，新指纹修订 3/3 页独立采齐，无混页；
   - C 采集器停机期间收到更正：停机窗口查询与停机前逐字节一致；重启后新指纹从头采、旧指纹完整保留；
   - D 原样重发（指纹不变）：复用已采的第 1 页，仅为缺页申请 1 次令牌续采完成；
   - E 时长变更（同版次号新 edition）：节目单侧采齐后旧结果保持可查、不提前切换；
     修复清单按新定义采齐后，时长/播放位置/缺失区段在同一事务整体切换，轮询无混合态。
7. **节目定位展示**：按母带/按节目输出可播放时间段（含 1.5x 变速段换算）与缺失母带区段。

数据文件：`data/archive.db`（手动运行）、`.verify/`（验证用，每次运行前清空）。
