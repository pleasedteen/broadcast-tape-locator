# 广播档案馆节目定位服务（本地模拟）

用 **TypeScript + Node.js + SQLite** 实现的节目定位服务，**零外部依赖**
（TypeScript 由 Node ≥ 22.18 原生类型擦除直接运行，SQLite 用内置 `node:sqlite`，
`npm install` 无包可装、瞬间完成）。

三个可启动组件 + 一条验证命令：

| 组件 | 启动 | 说明 |
|---|---|---|
| 模拟站点 | `npm run site` | 本地模拟清单站点（不依赖真实外站），端口 4181 |
| 同步入口 | `npm run sync` | 采集器守护进程，断点续采、暂停避让、令牌恢复；**同一数据库可并行跑多个进程**（来源租约分片、卡住接管） |
| 查询接口 | `npm run api` | 只读查询服务，端口 4182，独立于采集器进程 |
| 一键验证 | `npm run verify` | 自动起停全部组件（含两个采集进程），约 17 秒（远低于 80 秒）跑完 7 阶段 35 项检查 |

## 快速开始

```bash
npm install        # 无依赖，瞬间完成（安装时间单算）
npm run verify     # 一条命令验证：双进程并行、卡住接管、暂停恢复、采集恢复、修订切换、节目定位
```

手动分步启动（三个终端 + 可选第四个）：

```bash
npm run site                              # 模拟站点 http://127.0.0.1:4181
SITE_URL=http://127.0.0.1:4181 \
DB_PATH=./data/archive.db POLL_MS=500 \
  npm run sync                            # 采集器进程 1
SITE_URL=http://127.0.0.1:4181 \
DB_PATH=./data/archive.db POLL_MS=500 \
WORKER_ID=sync-2 \
  npm run sync                            # 采集器进程 2（同一数据库，可选）
DB_PATH=./data/archive.db PORT=4182 \
  npm run api                             # 查询接口 http://127.0.0.1:4182
```

环境变量：`PORT`（site/api 端口）、`SITE_URL`、`DB_PATH`、`POLL_MS`（采集轮询间隔）、
`WORKER_ID`（采集进程标识，同一库上各进程须唯一）、`LEASE_MS`（来源租约时长，默认 2000ms）、
`HTTP_TIMEOUT_MS`（单个请求超时，默认 3000ms）。

## 领域模型

- **母带 / 时间轴版次**：每盘母带有若干时间轴版次（各有时长）。两类清单的每次修订都标明所用版次。
- **节目单**：节目在母带时间轴上的时间段；每次修订给出整盘母带的完整节目单。
- **修复清单**：母带区段在各数字副本中的位置；修复时剪掉损坏录音（损坏记录），
  并支持分段变速（`rate` 段内恒定，副本时长 = 母带时长 / rate）。
- **生效规则**：每盘母带查询采用「两类清单均已采齐」的**最新共同时间轴版次**，
  同版次两侧各取**最新完整修订**。任一完整修订采齐时，生效指针在单个 SQLite 事务内切换，
  因此同一次查询中的播放位置和缺失区段必然一起更新；被新版清单移除的记录随该修订一并撤下。
- **可用性**：查询接口只读 SQLite（WAL），与采集器进程隔离——同步中、来源暂停、
  采集器重启期间，查询持续提供此前可用结果；已采齐的修订即使被站点撤下也继续可用。

## 查询接口（4182）

| 路由 | 说明 |
|---|---|
| `GET /tapes` | 母带列表及当前生效版次 |
| `GET /tapes/:tape` | 母带视图：节目单 + 各副本可播放时间段 + 该副本缺失的母带区段 |
| `GET /tapes/:tape/programs` | 当前生效节目单 |
| `GET /tapes/:tape/programs/:pid` | 节目视图：母带范围 + 各副本可播放时间段 + 缺失区段 |
| `GET /programs/:pid` | 按节目跨母带查询 |
| `GET /sync/status` | 同步进度：在线采集进程、各来源会话/暂停状态/租约持有者、每修订进度（已采/总页数）、待补齐清单已采到的损坏记录位置 |
| `GET /health` | 存活检查 |

响应示例（`GET /tapes/T1/programs/P2`，时间为毫秒）：

```json
{
  "tapeId": "T1", "timelineVersion": 1, "programRevision": 1, "restorationRevision": 1,
  "program": { "id": "P2", "title": "戏曲选段", "masterRange": [900000, 2700000] },
  "copies": [
    { "copyId": "C1",
      "playable": [ { "master": [900000, 1200000], "copy": [900000, 1200000] } ],
      "missing":  [ { "master": [1200000, 1500000], "note": "磁带霉变，信号丢失" } ] }
  ]
}
```

无共同版次时返回 `404 NO_ACTIVE_VERSION`；节目不在当前生效修订中时返回 `404 PROGRAM_NOT_FOUND`。

## 模拟站点协议（4181）

- `GET /api/sources` — 来源（母带）列表
- `POST /api/sources/:tape/session` — 建立会话；**站点同时轮换签名令牌**；暂停中返回 `423 {pausedUntil}`
- `GET /api/sources/:tape/index?sessionId=` — 时间轴版次 + 在架修订索引（附当前签名令牌）
- `POST /api/sources/:tape/page-tokens` — 申请**一次性翻页令牌**；修订已撤下返回 `410`
- `GET /api/sources/:tape/page?sessionId=&pageToken=&sig=` — 取页。
  `sig = sha256(签名令牌|会话|翻页令牌)`，随站点刚发出的令牌和当前会话变化；
  签名过期返回 `409 STALE_SIGN_TOKEN`（附新令牌，翻页令牌不消耗）；
  令牌已消费返回 `409 PAGE_TOKEN_CONSUMED`；**响应可能丢失而令牌已消费**（站点直接断开连接），
  需重新申请令牌续采。页面有 `table` / `cards` 两种排版，按页交替。

演示控制接口：`POST /control/publish`（发布修订）、`/control/pause`（暂停来源，恢复后旧会话作废、发放新会话）、
`/control/withdraw`、`/control/withdraw-after`、`/control/lose-response`、`/control/slow-page`（取页延迟，模拟本地慢页）、
`/control/rotate-token`、`GET /control/state`。

## 同步与恢复语义

- **断点续采**：页级进度落库（`pages` 检查点 + `revisions.pages_done`），页入库幂等；
  采集器重启后已采齐修订直接复用不重采，未采齐的从下一页继续。
- **多进程并行**：同一数据库可跑多个采集进程。每个来源一把租约
  （`sources.owner_id / lease_epoch / lease_expires_at`，单事务抢占），同一时刻只有一个持有者；
  进程每轮最多新认领一个来源，自然分片；各来源取页循环并发运行，本地慢页时多个来源的取页实际重叠。
- **卡住接管**：持有者逐页续租；进程卡住（事件循环阻塞）但还活着时，租约到期（默认 2 秒），
  其他进程在 3 秒内接手该来源，从已落库的页之后继续（不重采已入库页）。
- **租约代栅栏**：会话与签名令牌绑定租约代（`session_lease_epoch`）；页面入库、索引对账、
  撤下标记都只在仍持有租约时落库——卡住进程恢复后，其晚到的旧响应被丢弃，
  不覆盖新持有者的进度或新一代会话。
- **撤下对账**：重启/轮询时与站点索引对账——未采齐且已撤下的修订标记 `abandoned`（进度与损坏记录仍可查），
  已采齐的保留可用。
- **暂停避让**：任一进程收到 `423` 后把 `paused_until` 落库，所有进程随即停止向该来源发任何请求；
  恢复后以新会话继续（旧会话已被站点作废）。某来源暂停或某盘采不齐时，其他来源照常同步；
  暂停期间定位查询持续可用。

## 一键验证的场景（`npm run verify`）

1. **双进程并行采集**：同一数据库启动两个采集进程；来源按租约互斥分片到两个进程；
   注入「本地慢页 900ms」，验证两个来源的取页在飞窗口实际重叠；
   注入「第 2 页响应丢失、令牌已消费」，采集器凭新令牌续采完成；两种排版均解析；
   T3 修复清单被中途撤下（采不齐），T1/T2 不受影响；待补齐清单可查进度与损坏记录位置。
2. **来源暂停**：T1 暂停 4 秒，任一进程登记暂停后两个进程都对 T1 零请求，T2 新修订照常同步生效，
   暂停期间定位查询持续可用。
3. **恢复与原子切换**：恢复后站点发放新会话；同版次节目单 rev2 生效，
   轮询验证任何一次查询结果要么全旧要么全新（无混合态）。
4. **新版次生效**：T1 时间轴 v2 两侧清单采齐后切换；被移除的 P3 随修订撤下（404）。
5. **进程卡住接管**：发布 4 页慢页清单，采到 2 页时把持有进程 SIGSTOP 卡住（进程仍存活）；
   另一进程 3 秒内租约接手、从已落库的页之后续采至采齐；恢复（SIGCONT）后，
   卡住进程晚到的旧响应被租约栅栏丢弃，不覆盖新进度或会话。
6. **采集器重启**：两个进程 SIGKILL 后站点已撤下 T1 全部 v1 修订；重启对账后已采齐修订保留复用、
   不重复抓取，T3 补齐后生效；重启窗口内查询结果不变。
7. **节目定位展示**：按母带/按节目输出可播放时间段（含 1.5x 变速段换算）与缺失母带区段。

数据文件：`data/archive.db`（手动运行）、`.verify/`（验证用，每次运行前清空）。
