# 广播档案馆节目定位服务（本地模拟，主备双站）

用 **TypeScript + Node.js + SQLite** 实现的节目定位服务，**零外部依赖**
（TypeScript 由 Node ≥ 22.18 原生类型擦除直接运行，SQLite 用内置 `node:sqlite`，
`npm install` 无包可装、瞬间完成）。

同一盘母带接入**主备两个模拟站点**（同一 `site.ts` 起两个进程：A=4181 主站、B=4183 备站），
两站会话、签名令牌、暂停状态各自独立，清单内容一致但分页大小可以不同。

四个可启动组件 + 一条验证命令：

| 组件 | 启动 | 说明 |
|---|---|---|
| 主模拟站点 A | `REPLICA_ID=A PORT=4181 npm run site` | 本地模拟清单主站 |
| 备模拟站点 B | `REPLICA_ID=B PORT=4183 npm run site` | 本地模拟清单备站（会话/暂停独立） |
| 同步入口 | `npm run sync` | 采集器守护进程，主备接力、断点续采、暂停避让、冲突拒收 |
| 查询接口 | `npm run api` | 只读查询服务，端口 4182，独立于采集器进程 |
| 一键验证 | `npm run verify` | 自动起停全部组件，约 7 秒（远低于 80 秒）跑完 8 阶段 53 项检查 |

## 快速开始

```bash
npm install        # 无依赖，瞬间完成（安装时间单算）
npm run verify     # 一条命令验证：主备接力、暂停独立、冲突拒收、节目定位
```

手动分步启动（四个终端）：

```bash
REPLICA_ID=A PORT=4181 npm run site                     # 主站 http://127.0.0.1:4181
REPLICA_ID=B PORT=4183 npm run site                     # 备站 http://127.0.0.1:4183
SITE_URL_A=http://127.0.0.1:4181 \
SITE_URL_B=http://127.0.0.1:4183 \
DB_PATH=./data/archive.db POLL_MS=500 \
  npm run sync                                          # 采集器（主备双站）
DB_PATH=./data/archive.db PORT=4182 npm run api        # 查询接口
```

环境变量：`SITE_URL_A` / `SITE_URL_B`（主备地址）、`SITE_URL`（单站兼容）、
`REPLICA_ID`（站点标识 A/B）、`PORT`、`DB_PATH`、`POLL_MS`。

## 领域模型

- **母带 / 时间轴版次**：每盘母带有若干时间轴版次（各有时长）。两类清单的每次修订都标明所用版次。
- **节目单**：节目在母带时间轴上的时间段；每次修订给出整盘母带的完整节目单。
- **修复清单**：母带区段在各数字副本中的位置；修复时剪掉损坏录音（损坏记录），
  并支持分段变速（`rate` 段内恒定，副本时长 = 母带时长 / rate）。
- **生效规则**：每盘母带查询采用「两类清单均已采齐」的**最新共同时间轴版次**，
  同版次两侧各取**最新完整修订**。任一完整修订采齐时，生效指针在单个 SQLite 事务内切换，
  因此同一次查询中的播放位置和缺失区段必然一起更新；被新版清单移除的记录随该修订一并撤下。
- **可用性**：查询接口只读 SQLite（WAL），与采集器进程隔离——同步中、来源暂停、
  采集器重启期间，查询持续提供此前可用结果；已采齐的修订即使被站点撤下也继续可用。

## 查询接口（4182）

| 路由 | 说明 |
|---|---|
| `GET /tapes` | 母带列表及当前生效版次 |
| `GET /tapes/:tape` | 母带视图：节目单 + 各副本可播放时间段 + 该副本缺失的母带区段 |
| `GET /tapes/:tape/programs` | 当前生效节目单 |
| `GET /tapes/:tape/programs/:pid` | 节目视图：母带范围 + 各副本可播放时间段 + 缺失区段 |
| `GET /programs/:pid` | 按节目跨母带查询 |
| `GET /sync/status` | 同步进度：每盘母带的持久/本轮站点、主备各自会话与暂停状态；每修订的记录级进度、各站分页/取页/在架/内容哈希冲突标记、时长冲突；待补齐清单已采到的损坏记录位置 |
| `GET /health` | 存活检查 |

响应示例（`GET /tapes/T1/programs/P2`，时间为毫秒）：

```json
{
  "tapeId": "T1", "timelineVersion": 1, "programRevision": 1, "restorationRevision": 1,
  "program": { "id": "P2", "title": "戏曲选段", "masterRange": [900000, 2700000] },
  "copies": [
    { "copyId": "C1",
      "playable": [ { "master": [900000, 1200000], "copy": [900000, 1200000] } ],
      "missing":  [ { "master": [1200000, 1500000], "note": "磁带霉变，信号丢失" } ] }
  ]
}
```

无共同版次时返回 `404 NO_ACTIVE_VERSION`；节目不在当前生效修订中时返回 `404 PROGRAM_NOT_FOUND`。

## 模拟站点协议（A=4181 / B=4183，两站同构）

- `GET /api/sources` — 来源（母带）列表
- `POST /api/sources/:tape/session` — 建立会话（响应含 `replicaId`）；**站点同时轮换签名令牌**；暂停中返回 `423 {pausedUntil}`
- `GET /api/sources/:tape/index?sessionId=` — 时间轴版次（含时长）+ 在架修订索引，
  每个修订附 `pageSize` / `pageCount` / `recordCount` 与整单 **`contentHash`**（仅取决于记录内容，与排版/分页无关）
- `POST /api/sources/:tape/page-tokens` — 申请**一次性翻页令牌**；修订已撤下返回 `410`
- `GET /api/sources/:tape/page?sessionId=&pageToken=&sig=` — 取页。
  `sig = sha256(签名令牌|会话|翻页令牌)`，随站点刚发出的令牌和当前会话变化；
  签名过期返回 `409 STALE_SIGN_TOKEN`（附新令牌，翻页令牌不消耗）；
  令牌已消费返回 `409 PAGE_TOKEN_CONSUMED`；**响应可能丢失而令牌已消费**（站点直接断开连接），
  需重新申请令牌续采。页面有 `table` / `cards` 两种排版，按页交替。

演示控制接口：`POST /control/publish`（发布修订）、`/control/pause`（**只暂停本站**该来源，
恢复后旧会话作废、发放新会话；另一站不受影响）、`/control/withdraw`、`/control/withdraw-after`、
`/control/lose-response`、`/control/rotate-token`、
`/control/page-size`（**仅本站**分页大小覆盖，制造主备分页不同）、
`/control/timeline-duration`（**仅本站**时长覆盖，制造时长冲突）、`GET /control/state`。

## 主备接力与同步语义

- **两站独立**：每盘母带在主站 A、备站 B 各维护独立会话、签名令牌、暂停截止，分别落库。
- **接力触发**：当前站点暂停（423）时**临时绕行**另一站（持久指针 `active_replica` 不变，恢复后自动回原站）；
  撤下（410）、会话失效（401）、网络不可达等**硬故障**则持久切换 `active_replica` 并落库，
  采集器重启后仍沿用新站，不回摆。
- **分页不同只取未采页**：页级断点按「修订 × 站点」独立记录（`replica_pages`）。
  接力到新站时按 `首个含未采记录的页 = floor(已采记录数 ÷ 本站页大小)` 续采，
  已在别站采过的页整页跳过；记录按内容哈希幂等汇入（`rev_records`），重叠页自动去重，绝不重复请求。
- **冲突拒收**：备站同号清单的 `contentHash` 与已采内容不同 → 置 `conflict=1` 并拒收该站此单；
  母带时长不同 → 只在 `timelines.conflict` 标记、保留首次基准时长。两者都**不覆盖已采数据、不动生效指针**。
- **断点续采**：记录级与页级进度落库，采集器重启后已采齐修订直接复用不重采，未采齐的继续。
- **撤下对账**：按站对账——本站撤下只标该站 meta；两站都撤下才把未采齐修订标记 `abandoned`
  （进度与损坏记录仍可查），已采齐的保留可用。
- **暂停避让**：`423` 后登记该站 `paused_until`，期间不向该站发任何请求；另一站照常服务。
- **生效规则不变**：采齐（`records_done == record_count`）后仍按「两类清单均已采齐的最新共同时间轴版次、
  同版次各取最新完整修订」在单事务内切生效指针，查询侧原子看到一致快照。

## 一键验证的场景（`npm run verify`，8 阶段 53 项）

1. **首次采集**：注入「第 2 页响应丢失、令牌已消费」，凭新令牌续采；两种排版均解析；
   T3 修复清单主备两站都采不齐（不影响 T1/T2/T4），待补齐清单可查进度与损坏记录位置。
2. **主站暂停 → 备站接力**：只暂停主站 A，期间对 A 零请求，备站 B 以独立会话采齐新修订；
   暂停只临时绕行（`last_replica=B`、`active_replica` 仍为 A）。
3. **恢复与原子切换**：主站恢复后发放新会话、自动回到 A；同版次节目单 rev2 生效，
   轮询验证任何一次查询要么全旧要么全新（无混合态）。
4. **新版次生效**：T1 时间轴 v2 两侧清单采齐后切换；被移除的 P3 随修订撤下（404）。
5. **采集器重启**：SIGKILL 后两站撤下 T1 全部 v1 修订；重启后已采齐修订保留复用、主备均不重复抓取，
   T3 补齐后生效；重启窗口内查询结果不变。
6. **主备接力核心**：T5 主站采到第 1 页（3/7 条）即 410 撤下 → 立即接力备站；SIGKILL 重启后
   仍从备站续采；两站分页不同（主 3 条/页、备 1 条/页），备站只请求第 4–7 页；备站独立暂停下零取页、
   恢复后采齐，T5 按共同版次规则生效。
7. **冲突与查询切换**：同号清单内容冲突被检出并拒收（定位结果不变）；母带时长冲突只标记、基准时长不变；
   采集器运行中 7 条查询路由随时可切、结果稳定。
8. **节目定位展示**：按母带/按节目输出可播放时间段（含变速段换算）、缺失母带区段与主备/冲突状态。

数据文件：`data/archive.db`（手动运行）、`.verify/`（验证用，每次运行前清空）。
